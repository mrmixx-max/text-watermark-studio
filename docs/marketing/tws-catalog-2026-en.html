What the studio can do — ten capabilities, one tool
1 · Detection
KGW watermarks on word AND BPE level, Z-score instead of "confidence %". Your own keys, no black box.
2 · Cleaning
Expose and strip AI markers (clean/dilute) — with documented effect, measured instead of promised.
3 · Your own marking
Sign documents with your own key (embed) — invisible, verifiable, provable.
4 · Provenance
HMAC signatures + key registry: who signed what, when? Provable.
5 · Metadata forensics
EXIF/XMP/C2PA/coordinates across 8 formats — the digital DNA of a file.
6 · Rewriting
LLM rewrite with 6 modes (structural, backtranslate etc.) — local via Ollama, any model name.
7 · Findings & watch
Report as PDF/HTML + directory watcher: monitoring without manual routine.
8 · Corpus comparison
MinHash similarity against your own documents — with quoted evidence, deterministic, offline.
9 · Measure robustness
Attack matrix + SynthID sweep: what actually breaks a watermark?
10 · Automation
CLI, API (FastAPI) and a menu-driven TUI with 25 actions. For humans and machines.

The honest foundation

Method over opinion. The studio produces numbers you can recompute: a Z-score, a Jaccard coefficient, an HMAC hash. It does not claim to "reliably detect AI" — it shows evidence and names the limits. That is what separates it from detector SaaS with unpublished "99%" claims.

One command, all worlds. ai-wm tui opens the menu UI (↑/↓ navigate, Enter runs). ai-wm detect file.txt for the CLI. ai-wm serve for the API. Same capabilities, three ways to work.

Application 1 · Journalism & Newsrooms

The problem

Press releases, wire copy and "research leaks" are now partly machine-generated or post-processed. At the same time, source protection has become existential: upload source material to a cloud detector and you no longer control it.

The solution

  • Check incoming documents: ai-wm detect dpa-copy.txt --json — style forensics, metadata, provenance in one finding.
  • Secure whistleblower material: ai-wm file-embed original.pdf — HMAC signature, chain of custody, tamper proof.
  • Guard your own archive: ai-wm similarity new-text.txt --corpus archive/ — reprint or fresh interpretation?
  • Monitoring: ai-wm watch ~/Downloads --interval 5 — every new document scanned automatically.

The honest note

A Z-score is a lead, not a verdict. The studio shows evidence; the newsroom decides. No external server ever sees the material — everything stays on the newsroom machine.

5-minute workflow

# 1. Check material
ai-wm detect source.pdf --json
ai-wm file-inspect source.pdf        # metadata: who created what?

# 2. Secure evidence (whistleblower file)
ai-wm file-embed source.pdf          # attach HMAC signature
ai-wm report source.pdf --key my-key # finding as PDF

# 3. Archive check before publishing
ai-wm similarity text.md --corpus ~/newsroom/archive

Application 2 · Science & Education

The problem

Exam boards need evidence, not gut feelings. Typical detectors deliver a "confidence bar" without statistics — and fail in court. Students need clear, reproducible criteria.

The solution

  • Evidence instead of accusation: ai-wm detect thesis.txt --key examiner-key — Z-score, token level, reproducible finding for the record.
  • Seminar-pool comparison: ai-wm similarity thesis.txt --corpus all_seminars/ — overlap with your own materials, evidence included.
  • Teaching: the KGW method is readable code (MIT) — a lesson in statistical watermarks, Z-scores and honest evaluation.
  • Research: attack matrix + sweep document robustness — for papers, no black box.

The honest note

No detector proves AI origin — it provides evidence. The studio declares its limits: style heuristics without a key, paraphrase weakening, no access to platform keys (e.g. SynthID). That honesty is the academic standard.

Example finding

ai-wm detect term-paper.txt --key 2026-summer --json
→ verdict: watermark_detected
→ z_score: 4.12   (threshold: 4.0)
→ token_level: bpe · gamma: 0.25 · key: 2026-summer
→ "The finding is reproducible — any department can
   recompute it with the same key."

Application 3 · Legal, Compliance & Insurance

The problem

Disputes revolve around documents: was the contract changed retroactively? Is this email real? Where does this piece of evidence come from? Metadata and signatures decide, not assumptions.

The solution

  • Integrity: ai-wm file-inspect contract.pdf — modification time, author, editing software, GPS coordinates of creation.
  • Signed chain of custody: ai-wm file-embed + registry — every version HMAC-protected, tampering visible instantly.
  • Clause comparison: ai-wm similarity new-contract.txt --corpus templates/ — which model clauses were reused, where does it deviate?
  • Inbound screening: watch on email attachments — before the client signs.

The honest note

The studio does not replace an expert report — it produces reproducible findings an expert report can build on. HMAC proves integrity since signing, not the authenticity of the origin.

Workflow "check an exhibit"

ai-wm file-inspect annex.pdf --json   # metadata report
ai-wm file-embed annex.pdf            # close the chain of custody
ai-wm report annex.pdf --key case-2026 --format pdf

Application 5 · Publishing, Content & Creators

The problem

Content producers want two things: (a) to prove what they created themselves, and (b) to spot when foreign content is reused without transformation. Platform watermarks (e.g. SynthID) only help the platform operator.

The solution

  • Your own mark: ai-wm embed article.md --key my-brand — invisible watermark, verifiable anytime.
  • Reuse checks: ai-wm similarity against competitor archives — with quoted evidence.
  • Editorial pipeline: batch + watch — check 100 articles automatically before publication.
  • Secure AI-assisted production: rewrite + detection — consistent processing of local-model output.

The honest note

"Pangram-safe" means: no known markers, no statistical signature, no steganography pattern. No guarantee against every future method — but a documented, traceable state in the release notes.

Content pipeline

for f in ./manuscripts/*.md; do
  ai-wm detect "$f" --json
  ai-wm embed "$f" --key publisher-2026
done
ai-wm batch ./manuscripts --action clean   # strip metadata

Application 6 · Research, Security & OSINT

The problem

Security and OSINT teams work with foreign files: torrents, leaks, captured documents. The questions are always the same: where does this come from? Is it manipulated? Does it carry hidden markers?

The solution

  • File triage: ai-wm file-inspect — metadata report in seconds before opening an unknown file.
  • Marker search: ai-wm detect on BPE level — the level real tokenizers feed.
  • Robustness research: attack matrix (paraphrase, Unicode, shuffle) + SynthID sweep — what survives which attack? Reproducibly documented.
  • Your own experiments: multi-model backend — any Ollama model as generator/checker for controlled trials.

The honest note

Statistical watermarks are no silver bullet: word permutation can break a KGW mark (measured in-repo: ΔZ ≈ −12.8). The studio documents these attack surfaces instead of hiding them — research needs exactly that truth.

Experiment setup

# Install a model (any Ollama model)
ai-wm llm install hf.co/bartowski/EuroLLM-9B-Instruct-GGUF:Q4_K_M
ai-wm llm list          # 22 models in the pool

# Measure robustness
ai-wm attack-matrix --fixture probe.txt
ai-wm synthid-sweep --rate 0.5

Application 7 · Development & Automation

The problem

Processes need checks nobody runs manually. CI pipelines, email inboxes, upload folders — every organization has a point where documents arrive and should be checked, but aren't.

The solution

  • API: ai-wm serve — FastAPI endpoints for detect, clean, embed, similarity. JSON in, JSON out.
  • Watch mode: ai-wm watch ./inbox --once — fits into any cron job, deterministic JSON lines.
  • CI gate: ai-wm detect in the pipeline — check release artifacts for markers, exit code 1 breaks the build.
  • TUI for humans, CLI for machines: the same 25 actions, two interfaces.

The honest note

Exit codes are strict: 0 = clean, 1 = finding/error/unavailable, 2 = input error. Automation builds on this contract — and the contract is tested (510 tests).

Examples

# CI gate
ai-wm detect build-artifact.md --key release-key \
  || echo "Marker found — stop the build"

# Cron watchdog
*/10 * * * * ai-wm watch /srv/inbox --once --report

# Python
from ai_watermark_toolkit.forensics.detect import detect_text
result = detect_text(open("document.txt").read(), key="my-key")

Honest limits — and the next step

What the studio cannot do (and says so)

  • No access to platform keys (e.g. SynthID) — verification there is platform-only.
  • No "99%" claims — style heuristics without a key are evidence, not proof.
  • Paraphrase weakens statistical watermarks — the attack matrix measures how much.
  • No plagiarism crawler — only similarity to your documents.
  • No silver bullet against determined attackers — but documented, measurable robustness.

This list is in the docs, not just in marketing. Honesty is the product.

Measurement over Magic — the counter-model

USP 1 · Keyed verification — "The right key shouts, the wrong one stays silent"

No percentage. A Z-score with a control group anyone can reproduce — that is the difference between a claim and proof.

  • Right-key z=15.9 · wrong-key z=−0.2 · unmarked control z=0.6 (real model, 304 tokens)
  • Every detection ships with control groups, p-value, green-rate and a reproducible command
  • In contrast: GPTZero/Originality return a cloud "99%" number nobody can rebuild

USP 2 · 100% local, offline, deterministic — "Your texts never leave the machine"

  • Zero telemetry, no cloud requirement, no data egress — privacy/GDPR as a built-in property, not an add-on
  • Deterministic core (stdlib-only, $0, MIT): Z-score test, HMAC provenance and MinHash all run locally
  • In contrast: SaaS detectors require uploading your documents

USP 3 · Dual-use — "One tool. Three directions: detect, mark, prove"

Detection, marking and signed provenance — in one CLI, one API, one TUI.

  • Statistical detection with your own key + active marking (post-hoc & experimental generation-time) + signed file provenance (HMAC-SHA256, 8 formats)
  • 25 CLI subcommands · 25 TUI actions · FastAPI · 80 MCP tools · strict exit-code contract 0/1/2
  • In contrast: SynthID is detection only (platform-bound), GPTZero/Originality are detection only without own keys

The honest limits — themselves a feature

  • Honestly measured robustness: style rewrites hold (ΔZ≈−2), word shuffle collapses (ΔZ≈−12.8) — the same limits platform vendors document.
  • Redlist sign semantics (z<0) and context windows c∈{1,2,4,8} — tested, not claimed.
  • 510 automated tests, 12-stage burn-in, security audits with regression tests — the repo hunts its own bugs.
  • No detector, no verdict: every finding ships with measurement, control group and a reproducible command.

An instrument that does not lie — in a market that just discovered how much magic-speak is out there.
